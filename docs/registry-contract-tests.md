# Registry contract baseline (#909)

This is the **current** implementation's executable baseline for the proposed [component architecture](component-architecture.md), not a public persistence API. Existing claims tests exercise today's personalized service; they are **not** a contract requiring a future standalone catalog to retain claims.

**Intentional corrections in this change:** operator event reconciliation now uses the full configured scope instead of the triggering namespace; startup queues a full refresh after cache sync even with no CRD events; list extraction enforces `registry-export=true` rather than relying only on watch predicates. These remove stale or non-opted-in exports. No new wire pagination or source/storage framework is introduced.

**Run the manager acceptance:** install the pinned tool (`go install sigs.k8s.io/controller-runtime/tools/setup-envtest@v0.0.0-20260125163108-a19ec76a3c5d`), then run `ENVTEST_RELEASES_INDEX="https://raw.githubusercontent.com/kubernetes-sigs/controller-tools/1031496fc98a4f51010c3bdfdeb57b5d67bea7bd/envtest-releases.yaml"; KUBEBUILDER_ASSETS="$(setup-envtest use 1.33.0 --index "$ENVTEST_RELEASES_INDEX" -p path)" go test -p 2 -race -tags=integration ./internal/kubernetes -run '^TestRegisteredStartupRefresh$' -count=1`. The index is pinned to immutable controller-tools commit `1031496fc98a4f51010c3bdfdeb57b5d67bea7bd`, rather than the mutable default index which follows its `main` branch. CI runs the same acceptance after the authz integration suite. The test fails rather than silently skipping if the API server binaries are unavailable. It explicitly disables existing-cluster mode (even if `USE_EXISTING_CLUSTER=true` is inherited), installs CRDs in an isolated envtest control plane, starts a leader-elected manager and checks delivery without manually calling Reconcile.

**Not frozen / outstanding conformance work:** A single HTTP+real-service boundary test and a ToolHive-client multipage walkthrough are not yet included. The startup suite uses a generated writer mock instead of a persisted writer; the removed namespace is represented by a CR outside the configured cache, not a real previously persisted source. Operator cancellation during a running Store still needs further coverage. Future public backends need shared black-box conformance for dedup at version limits, malformed/mismatched cursors, managed latest after every deletion, and lease/fencing/reconfigure races. Current version ordering uses `model.CompareVersions` (semver group above non-semver, semantic precedence then exact raw spelling; lexical within non-semver) and is a total order. Existing latest pointers are repaired synchronously in the database storage factory during app construction, before either public or internal HTTP server is built/started; failure aborts construction (the readiness probe only checks DB connectivity after startup). The transaction locks `source`, `registry_entry`, `entry_version`, and `latest_entry_version` in `SHARE ROW EXCLUSIVE` mode before scanning, with a five-second lock-wait timeout. Concurrent new writers wait or finish before the scan. **Stop/drain all old-binary writers before upgrading:** rolling mixed-version writers are unsupported. This on-start repair is intended for small registries. It preserves snapshots, payloads and claims. A legacy cross-kind same-name collision retains its previously pointed kind because `latest_entry_version` is still keyed by `(source_id,name)` rather than `(source_id,kind,name)`; if there is no pointer, repair warns and leaves the ambiguous name without latest. Recover by removing/renaming the conflicting entry or selecting an existing kind's pointer; future #910 work must address the key shape. Resolve whole-name source selection, cross-kind operator identity and cursor compatibility deliberately before freezing #907's public contracts. Do not retain host claims expectations in the future catalog.
